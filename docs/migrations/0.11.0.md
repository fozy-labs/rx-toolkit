# Миграция с версии 0.10.x на 0.11.0

## Query

Релиз унифицирует словарь запуска у ресурсов и команд: `trigger` перестаёт означать три разных контракта. Конверт `TTriggerResult`, введённый в 0.10.0, удалён — агентский/хуковый `trigger` снова возвращает нативный промис, а проблема unhandled rejection решена внутри агента.

| Уровень | Было (0.10.x) | Стало (0.11.0) |
|---|---|---|
| `Command` (ядро) | `trigger(args, key?)` → сырой `Promise<TData>` | `execute(args, key?)` — тот же контракт; `trigger` **deprecated** |
| `CommandAgent` / `useCommand` | `trigger(args)` → конверт `TTriggerPromise` (не реджектится) | `trigger(args)` → **нативный** `Promise<TData>` (реджект пред-обработан) |
| `Resource` | `trigger(args, doForce?)` → `void` | **deprecated** → `prefetch(args)` / `prefetch(args, { force: true })` |

### Агентский / хуковый `trigger` — нативный промис вместо конверта

`trigger` из `useCommand` и `CommandAgent.trigger` возвращает обычный `Promise<TData>`: данные при успехе, реджект нормализованной через `mapError` ошибкой при провале.

#### Проверка конверта → try/catch

```tsx
// Было (0.10.x)
const result = await trigger({ text });
if (result.status === 'error') {
    console.error(result.error);              // ❌ поля status/error/data больше нет
} else {
    console.log(result.data);
}

// Стало
try {
    const data = await trigger({ text });     // ✅ данные напрямую
    console.log(data);
} catch (error) {
    console.error(error);                     // ✅ TError после mapError
}
```

> ⚠️ В типизированном коде компилятор укажет на все такие места (`.status` исчез из типа результата). В нетипизированном коде проверка `result.status === 'error'` перестанет срабатывать **молча** — грепните `\.status` рядом с вызовами `trigger`.

#### `.unwrap()` → убрать

`unwrap()` больше не существует — сам промис уже «бросающий»:

```typescript
// Было
const data = await agent.trigger({ text: 'Задача' }).unwrap();   // ❌

// Стало
const data = await agent.trigger({ text: 'Задача' });            // ✅
```

#### Fire-and-forget — по-прежнему безопасен

Реджект пред-обработан внутри агента (внутренний no-op catch), поэтому игнорирующий вызов не порождает unhandled rejection, а ошибка отражается через `state.isError`:

```typescript
void trigger({ amount: 100 });                // ✅ как и в 0.10.x, catch не нужен
```

#### Типы

```typescript
// Было
import type { TTriggerPromise } from '@fozy-labs/rx-toolkit';
let onSubmit: (args: TArgs) => TTriggerPromise<TData>;  // ❌ тип удалён

// Стало
let onSubmit: (args: TArgs) => Promise<TData>;          // ✅
```

Удалены: `TTriggerResult`, `TTriggerPromise`, `wrapTrigger`.

### `Command.trigger` → `Command.execute`

Чистое переименование, контракт идентичен (сырой промис, реджектится, `mapError`). Старое имя работает с пометкой `@deprecated` и будет удалено в одном из следующих релизов:

```typescript
// Было
await addTodoCommand.trigger({ text: 'Задача' }, 'my-key');

// Стало
await addTodoCommand.execute({ text: 'Задача' }, 'my-key');
```

### `Resource.trigger` → `prefetch`

Императивный API ресурса (`ensure` / `fetch` / `prefetch`) стабилизирован — с него снят `@experimental`. `Resource.trigger` объявлен `@deprecated`; замена:

```typescript
// Было
usersResource.trigger({ page: 1 });          // запустить, если ещё нет
usersResource.trigger({ page: 1 }, true);    // форс-перезапрос

// Стало
void usersResource.prefetch({ page: 1 });
void usersResource.prefetch({ page: 1 }, { force: true });
```

Общее сохраняется: запись создаётся синхронно, промис (`Promise<void>`) никогда не реджектится. Но замена **не тождественна** — различия сосредоточены на записи в состоянии `error`:

- `prefetch(args)` (без `force`) **ретраит упавшую запись** (он делегирует в `ensure`), тогда как старый `trigger(args)` был на ней no-op. Код, который «замолкал» после ошибки (например, периодический прогрев), после механической замены начнёт повторять запрос при каждом вызове. Если это нежелательно — проверяйте состояние перед вызовом: `if (!resource.getState(args).isError) void resource.prefetch(args)`.
- `prefetch({ force: true })` на упавшей записи тоже делает `retry`. Старый `trigger(args, true)` на ней фактически был no-op: его force-путь шёл через `refresh()`, который невалиден из состояния `error` и лишь писал предупреждение в консоль. То есть ретрай упавшей записи — **новое** поведение force-пути, а не замена одного перезапуска другим.
- `prefetch` удерживает keepalive-подписку на запись до завершения загрузки — отсчёт `retentionTime` стартует позже, чем при старом `trigger` (заметно только при очень маленьком `retentionTime`).

### Что не изменилось

- Реактивное состояние (`TCommandAgentState`: `status`, `data`, `error`, `isLoading`, `isSuccess`, `isError`, `retry`) — код, читающий состояние из `useCommand` / `state$`, менять не нужно.
- Ретраи и request id — `retry()` и стабильность ключа идемпотентности работают как раньше.
- `ensure` / `fetch` — сигнатуры и семантика прежние (изменился только статус стабильности).
- `mapError` — все реджекты мутаций по-прежнему нормализованы; теперь это касается и реджекта агентского `trigger`.

# Инстанс и узлы

Инстанс — дерево узлов, повторяющее [определение](definition.md). Узел — обычный объект с `$`-сигналами и действиями.

## Создание

```typescript
const form = FormSignal.state(RegistrationForm, {
    state: { name: "Ann", phones: [{ number: "+7 900 000-00-00" }] },
    context: { id: "42" },
    key: "registration/42",
});
```

| Опция | Что это | По умолчанию |
|---|---|---|
| `state` | начальные значения; они же база, от которой считается `isDirty$` | `defaultValue` полей |
| `context` | [контекст инстанса](definition.md#контекст-инстанса); обязателен, если определение его требует | — |
| `key` | ключ [devtools](#devtools), читается один раз | `name` корня |

- **`FormInitial<D>`** — тип `state`: поле принимает свой вход целиком, у группы все ключи необязательны, список — массив `FormInitial` строки.
- **Правило присутствия** (одно для `state`, `initialize`, `push`, `insert`): значение передано, если ключ есть и значение `!== undefined`; `null` — это значение.
- Создание без побочных эффектов: ни подписок, ни таймеров, ни запросов.

Через `api` определение создаёт `api.defineForm`, в React инстанс создаёт [`useForm`](react.md#useform).


## Адресация и снимки

- **`$` помечает реактивное чтение**: `form.fields.email.value$()`, `form.fields.phones.get$(key)`. В определении имена без `$`, в инстансе — с ним.
- **Дети группы — в `fields`**: `form.fields.services.fields.tariff`, строка списка — `form.fields.phones.items$()[0].fields.number`. Так новые члены узла не конфликтуют с именами полей.
- **Алиас снимка**: `form.fields.email$ === form.fields.email.state$`; у корня только `form.state$`.
- **`state$` не содержит значений потомков.** Значение группы или списка читается через `value$` / `parsed$`; иначе подписчик корневого снимка просыпался бы на каждый символ в любом поле. Снимок сравнивается поверхностно: ввод в одно поле не будит `state$` другого.
- Действия — стабильные ссылки, их можно передавать как колбэки: `onBlur={form.fields.email.blur}`.


## Узел поля

| Член | Что это |
|---|---|
| `state$` | снимок `{ value, parsed, visibleErrors, visibleWarnings, isValid, isPending, isFocused, isTouched, isModified, isDirty, isRequired, isDisabled }`; каждый ключ — одноимённый член узла |
| `value$` | текущее значение (вход схемы) |
| `parsed$` | `{ isParsed: true; value: Output } \| { isParsed: false; value: undefined }` |
| `issues$`, `errors$`, `warnings$`, `visibleErrors$`, `visibleWarnings$` | см. [Issue](validation.md#issue) |
| `isValid$` | схема проходит и нет error-issue |
| `isPending$` | запрос поля в полёте или в debounce |
| `isFocused$` | между `focus()` и `blur()` |
| `isTouched$` | был `blur()` или `markTouched()` |
| `isModified$` / `isDirty$` | см. [Черновик и база](#черновик-и-база) |
| `isDisabled$` | см. [Условные поля](validation.md#условные-поля-disabled) |
| `isRequired` | опция `required`, не сигнал |
| `queries.<k>` / `queries.<k>$` | см. [Узел запроса](validation.md#узел-запроса) |
| `set(value)` | ничего не делает, если значение `equals` текущему; иначе пишет черновик и снимает серверные issue поля |
| `focus()` / `blur()` | события ввода; `blur()` ставит touched |
| `markTouched(touched = true)` | |
| `reset()` | к базе: снимает черновик, touched, `submitted` и серверные issue |


## Узел группы

| Член | Что это |
|---|---|
| `fields.<name>` / `fields.<name>$` | узел ребёнка и алиас его `state$` |
| `state$` | `{ isValid, isPending, isTouched, isModified, isDirty, hasVisibleErrors, visibleErrorCount, isDisabled }` — без значений |
| `value$` / `parsed$` | композиция детей; `parsed$` не разобран, если не разобран хоть один ребёнок |
| `computed.<k>$`, `queries.<k>` | объявленные в определении |
| `ownIssues$` | issue самой группы: её правила, упавшие колбэки, серверные issue без пути внутрь |
| `issues$` и остальные списки issue | свои и всех включённых потомков |
| `isValid$` | все включённые потомки валидны и нет своих ошибок |
| `isPending$`, `isTouched$`, `isModified$`, `isDirty$` | любой включённый потомок или сама группа |
| `isDisabled$` | |
| `markTouched(touched = true)`, `reset()` | каскадом |
| `initialize(data?, options?)` | см. [reset и initialize](#reset-и-initialize) |


## Корень

Корень — группа с контекстом и состоянием сабмита:

| Член | Что это |
|---|---|
| `state$` | снимок группы и `{ status, isSubmitting, submitCount, canSubmit }` |
| `context$` | контекст инстанса |
| `submit({ force? })` | `Promise<boolean>`, см. [Сабмит](submit.md) |
| `status$`, `isSubmitting$`, `canSubmit$`, `submission$`, `submitAttempts$`, `submitCount$`, `entryKey` | см. [Состояние сабмита](submit.md#состояние-сабмита) |
| `clearIssues()` | снимает все серверные issue дерева |
| `initialize({ state?, context? }, options?)` | у корня принимает и контекст |


## Узел списка

| Член | Что это |
|---|---|
| `state$` | снимок группы и `items` — тот же массив, что `items$()` |
| `items$` | узлы строк; просыпается только при добавлении, удалении и перестановке |
| `get$(key)` | узел строки по ключу или `undefined` |
| `value$` / `parsed$` | массив значений строк |
| `ownIssues$`, `issues$`, флаги | как у группы |
| `push(initial?)` / `insert(index, initial?)` | добавляет строку из `FormInitial` строки и возвращает её узел |
| `remove(item)`, `move(item, to)`, `swap(a, b)`, `clear()` | `item` — ключ, индекс или узел строки; неизвестная строка игнорируется |
| `markTouched(touched = true)`, `reset()` | каскадом |

Узел строки — узел поля или группы с полем `key`. Ключ стабилен на всё время жизни строки: это React-`key` строки и идентичность её meta. `remove` и `move` переносят узел целиком — с touched, issue и запросами.

```tsx
const phones = useSignal(form.fields.phones$);

{phones.items.map((row) => (
    <PhoneRow key={row.key} row={row} onRemove={() => form.fields.phones.remove(row)} />
))}
```


## Черновик и база

У поля одно состояние: база и, возможно, черновик.

- **`isModified$`** — черновик есть: был `set()` нового значения. Остаётся `true`, даже если значение вернули к базе.
- **`isDirty$`** — черновик есть и не `equals` базе.
- **База** задаётся начальным `state`, `initialize` и успешным сабмитом (становится тем, что отправлено).

У списка своя структурная база — порядок ключей строк. `isDirty$` списка — структура отличается от базы или грязна любая строка; `isModified$` — структура менялась или изменена любая строка. Удалённая строка, ключ которой ещё в базе, сохраняется отсоединённой: `reset()` возвращает тот же узел с тем же ключом.


## reset и initialize

| Операция | Значения | База | Контекст | touched / `submitted` | Серверные issue | Состояние сабмита |
|---|---|---|---|---|---|---|
| `reset()` | ← база | не меняется | не меняется | снимаются | снимаются | сбрасывается (корень) |
| `initialize()` | ← `defaultValue` | ← `defaultValue` | не меняется | снимаются | снимаются | сбрасывается |
| `initialize({ state })` | ← `state` | ← `state` | не меняется | снимаются | снимаются | сбрасывается |
| `initialize({ state }, { keepDirtyValues: true })` | черновики сохраняются | ← `state` | не меняется | следуют за значением | следуют за значением | не меняется |
| `initialize({ context })` | не меняются | не меняется | ← `context` | не меняются | не меняются | не меняется |

- **`initialize()` без аргументов** — «очистить форму после успеха»; контекст остаётся.
- **Данные, пришедшие позже** (ресурс догрузился), идут через `initialize({ state })`, а не через новый инстанс. В React это делает [`useForm`](react.md#синхронизация-init).
- **Поля вне `state`** не меняются. `state` и `context` можно передать вместе; `context` принимает только корень.
- **`keepDirtyValues`** сохраняет черновик, только если он отличается и от старой базы, и от новой. touched, `submitted` и серверные issue снимаются только с полей, значение которых заменено.
- **Списки сопоставляются по индексу**: первые N строк сохраняют ключи и получают свой `initialize`, лишние удаляются, недостающие создаются — React не перемонтирует строки. `keepDirtyLists` (по умолчанию равен `keepDirtyValues`) сохраняет список с изменённой структурой; данные для него откладываются, и `reset()` применяет последние отложенные.
- `reset()` списка возвращает базовую структуру: удалённые строки возвращаются, добавленные удаляются, порядок — базовый.
- `initialize` есть у групп и корня; `reset` и `markTouched` — у всех узлов.


## Время жизни

Инстанс — граф значений, а не актор: у него нет `start()`, `stop()` или `dispose()`. Инстанс без ссылок собирает GC, записи ресурсов — `retentionTime` кэша.

Поля, группы, списки, правила, `computed` и `disabled` — чистые вычисления. Активность есть только у [запросов](validation.md#активность) и у [сабмита](submit.md), и живёт, пока есть потребитель:

| Ресурс | Кто держит | Когда отпускается |
|---|---|---|
| подписка на ключ запроса, таймер debounce, удержание записи ресурса | потребители узла запроса, в том числе через зависимые сигналы (`issues$`, `isValid$`, `state$` узлов) | с уходом последнего потребителя |
| ожидание запросов в `submit()` при `"wait"` | промис `submit()` | когда ожидание закончилось |
| запись команды | корень, пока идёт попытка | на settle, дальше `retentionTime` команды |
| применение результата попытки | промис команды | на settle |
| запись ресурса без потребителей | кэш | по `retentionTime` ресурса |

- Попытка сабмита, дошедшая до команды, завершается и применяется к инстансу независимо от UI; после размонтирования результат ложится в недостижимый инстанс.
- Удалённая строка не требует уничтожения: агрегаты перестают её читать, её запросы остывают.

Вне React активность держит подписка пользователя:

```typescript
const form = FormSignal.state(RegistrationForm);
const sub = form.state$.obs.subscribe(render); // запросы горячие
sub.unsubscribe(); // запросы остыли, форма пригодна к работе
```


## Devtools

В [Redux DevTools](../devtools/README.md) видны записываемые состояния формы под ключом инстанса и путём узла; вычисляемые сигналы скрыты, они следуют из записываемых.

| Ключ | Что в нём |
|---|---|
| `<key>/<путь>/input$` | поле: `{ default, value? }` — база и черновик |
| `<key>/<путь>/meta$` | touched, focus, `submitted` |
| `<key>/<путь>/server$` | серверные issue узла |
| `<key>/<путь>/keys$` | список: `{ baseKeys, keys? }` — базовый и текущий порядок строк |
| `<key>/context$`, `<key>/submit$`, `<key>/submitIssues$` | корень: контекст, фаза, исход и счётчики сабмита, issue упавшего хендлера |
| `<key>/<путь>/queries.<k>$` | состояние узла запроса |

Строка списка входит в путь своим ключом (`registration/phones/k2/number/input$`).

- **Ключ по умолчанию — `name` корня**, поэтому два инстанса одной формы без `key` делят записи. Передавайте уникальный `key` (`profile/${id}`).
- **Запись узла запроса остаётся до перезагрузки страницы**: у неё нет финализатора, в отличие от остальных записей, которые убирает сборка мусора. Касается только подключённых devtools, то есть dev.
- Инстанс, отброшенный StrictMode, виден в devtools до сборки мусора.

# Автоматическая ревалидация

`invalidateOn` автоматически помечает данные устаревшими и запускает повторный запрос по возвращении приложения в фокус, после восстановления сети или по интервалу. Обновление сохраняет SWR: пока запрос выполняется, текущие данные остаются доступны.

```typescript
const api = createApi({
    invalidateOn: { focus: true, reconnect: true },
});

const users = api.createResource({
    queryFn: loadUsers,
    invalidateOn: { interval: 10_000 },
});
```

## Политики и слияние

`focus` реагирует на переход `focused: false → true`, `reconnect` — на `online: false → true`. `true` эквивалентно порогу `0`; число задаёт минимальное время (мс), которое приложение должно провести без фокуса или сети. Отрицательное число нормализуется в `0`, `Infinity` никогда не проходит порог, а `false`, `undefined`, `NaN` и неподходящее значение отключают правило. Функция с исключением записывает `console.error("[Resource] invalidateOn.<key> threw", error)` и пропускает только эту запись.
Если фокус и подключение к сети восстанавливаются в одном отчёте драйвера, запись ревалидируется только один раз.

`interval` задаёт положительный период в миллисекундах (не больше 2 147 483 647 мс (~24,8 суток)) или функцию, возвращающую период либо `false`. Некорректные значения выключают таймер без предупреждения; исключение функции записывается через `console.error("[Resource] invalidateOn.interval threw", error)` и выключает данное вычисление.

Функциональные значения получают `(args, state)` отдельно для каждой записи. `state` совпадает с состоянием записи, которое возвращает `getState`, и включает `updatedAt`:

```typescript
const users = api.createResource({
    queryFn: loadUsers,
    invalidateOn: {
        focus: (_, state) => state.updatedAt === null || Date.now() - state.updatedAt > 30_000,
        interval: (_, state) => (state.hasData && state.data.done ? false : 1_000),
    },
});
```

Опция API служит значением по умолчанию. Ресурс переопределяет каждый ключ независимо; явный `undefined` наследует значение API. `invalidateOn: false` на ресурсе отключает все правила, а объект `{ focus: false }` отключает только фокус и сохраняет унаследованные `reconnect` и `interval`. Если ни одно правило не может сработать, монитор среды не подключается.

## Интервальный таймер

Для каждой записи отдельный таймер отсчитывает период с момента завершения последнего запроса. Поэтому медленный запрос не перекрывается следующим; ручная инвалидация, фокус, повтор после ошибки и любой другой запуск сбрасывают отсчёт. Функция интервала вычисляется заново при каждом запуске таймера и может вернуть `false`, например когда данные достигли конечного состояния.

Таймер работает только пока запись удерживается, вкладка видима и устройство онлайн. При отпускании записи, скрытии страницы или потере сети он приостанавливается, не удерживая запись от удаления. Если срок уже истёк к моменту нового удержания или возврата видимости/сети, запрос планируется асинхронно сразу. Открытый `Observable` остаётся запросом в полёте и не запускает опрос.

## Ошибки и запросы в полёте

Автоматическая ревалидация использует `retry()` для активной записи в `error` или `invalidate-error`: ошибка остаётся на экране до результата повтора. Для остальных записей она использует `invalidate({ inFlight: "join" })`, независимо от `invalidateInFlight` ресурса. Уже выполняющийся запрос присоединяется; более сильная отложенная политика (`trail` или `cancel`) не ослабляется. Тающая запись только получает метку и выполнит повтор при следующем удержании.

## Драйвер среды и SSR

По умолчанию API использует `browserEnvironmentDriver()`, который следит за видимостью, фокусом и подключением. Он подключается лениво только при создании ресурса с включённой политикой. В SSR отсутствие `window` не устанавливает слушатели; браузерный драйвер сообщает `visible: false`, поэтому интервалы не запускаются до появления среды. Передача `environmentDriver: null` отключает события среды, но оставляет интервальные таймеры работающими — удобно для Node и тестов.

Можно передать собственный источник состояния, например адаптер для React Native:

```typescript
import type { IEnvironmentDriver, TEnvironmentState } from '@fozy-labs/rx-toolkit';
import { AppState } from 'react-native';

let subscription: { remove(): void } | undefined;
const read = (): TEnvironmentState => {
    const active = AppState.currentState === 'active';
    return { visible: active, focused: active, online: true };
};

const environmentDriver: IEnvironmentDriver = {
    connect(onChange) {
        const report = () => onChange(read());
        subscription = AppState.addEventListener("change", report);
        return read();
    },
    disconnect() { subscription?.remove(); },
};
```

Состояние `online` можно подключить из NetInfo тем же способом.

В приложении используйте корректные подписки на фокус и сеть, а `disconnect()` оставьте для собственного teardown или тестов: ядро подключает монитор один раз и не вызывает `disconnect()`.

Проекционные ресурсы не принимают `invalidateOn`: их внутренние записи id-наборов — открытые стримы, поэтому интервальный таймер не мог бы запуститься. Автоматическая политика API к ним не применяется. Повторный запрос обёрнутого ресурса также не обновляет уже живые проекции — это то же ограничение, что и у ручного `invalidate`.

## `updatedAt`

Поле `updatedAt` в публичном состоянии обозначает время загрузки именно тех данных, которые сейчас показаны:

- `null` для отсутствующих данных и плейсхолдера;
- timestamp предыдущей записи для `dataSource: "previous"`;
- timestamp текущей записи для `dataSource: "current"` (включая гидрацию и SWR-перезапрос).

По нему удобно отбрасывать слишком свежие обновления, как в примере с порогом фокуса выше. В пользовательских типах состояния, ручных объектах и моках теперь нужно указывать новое поле.
